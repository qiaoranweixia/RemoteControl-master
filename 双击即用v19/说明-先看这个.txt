【RemoteControl 双端 · v19】2026-09-27
==================== 怎么用 ====================
不用脚本、不用 bat、不用右键"以管理员运行"。
1) 【被控端】RemoteControl.exe 拷到目标电脑 -> 双击 -> UAC 点【是】-> 完事。
   之后它自己常驻,并写进三层自启(服务 + 计划任务 + 注册表 Run)。
2) 【控制端】client.exe 双击 -> 输入被控端 IP -> 连接。
   首次双击会弹一次"开机自启已装好"的提示框,看到就说明成功了。

============== 本版改了什么(v19) ==============
【音频】系统声音采集全面增强,不依赖"立体声混音",也不要求插着喇叭:
  - 采集方式 = WASAPI 环回(LOOPBACK),抓的是"播放端点的数据流"本身,
    只要系统在渲染声音就能抓到,跟有没有接音箱/耳机无关。
  - 不再只认"默认设备":现在会枚举【全部】音频端点(含 未插入/已禁用/不存在),
    按 可用性 + 虚拟声卡优先 排序,逐个尝试,第一个成功的就用。
    (实测本机从"只有 1 个默认设备"变成 19 个候选)
  - 音频服务(AudioEndpointBuilder / Audiosrv)被停了或被禁用 -> 自动拉起再采。
  - 一个可用端点都没有 -> 自动启用【已禁用】的音频设备,然后再重试一轮。
  - 系统当前没在放任何声音时,主动补静音包,控制端不会"卡住/断流"。
  - 彻底采不到时,控制端会收到明确原因(已尝试几个候选+建议装虚拟声卡)。
【自启】修掉"换了目录/版本后永远不重新部署"的 bug:
  以前只判断"服务/任务/注册表项在不在",不判断它们指向哪个 exe;
  残留的旧路径会让部署被整体跳过 -> 重启后去拉不存在的旧程序。
  现在三者都会逐字比对【当前这份 exe 的路径】,不一致就自动重装(幂等)。

============== 如果被控端"完全没有声卡" ==============
硬件上不存在任何音频设备(设备管理器里也没有)时,Windows 自身就没有可播的端点,
环回自然无从抓起 —— 这是系统限制,任何远控软件都一样。
解决办法(任选其一,装完重启被控端程序即可):
  - 装一个免费虚拟声卡:VB-Cable (vb-audio.com/Cable) 或 ToDesk/向日葵自带的虚拟声卡;
  - 有些主板在 BIOS 里禁用了板载声卡,进 BIOS 打开 "HD Audio" 即可;
  - 设备管理器里若音频设备是"已禁用"状态,v19 会自动帮你启用。

============== 排查 ==============
被控端目录下(或 --log 指定的路径)有 agent.log;
服务模式另有 service.log。看 "audio:" 开头的行即可定位。

============== 注意 ==============
  - 被控端文件夹别改名/移动(服务里存的是绝对路径);真要搬,搬到新位置重新双击一次。
  - 重启电脑后需要有人登录一次 Windows(锁屏也算),抓屏/键鼠/抓音都要在桌面会话里做。
  - 彻底卸载:命令行执行 RemoteControl.exe --uninstall
